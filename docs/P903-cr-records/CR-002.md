変更要求: [`docs/P901-cr-direction/CR-002.md`](../P901-cr-direction/CR-002.md)

## スコープ決定(P903が着手前に記載)

### 影響カテゴリの分類

* [ ] UI表示文言のみ
* [ ] 画面項目追加・変更(バックエンド契約変更なし)
* [x] API契約変更 — `GET /api/health` の `mcp` を削除、エラーコード `MCP_UNAVAILABLE` を削除(その他のエンドポイントは変えない)
* [ ] データモデル変更 — SQLite のスキーマは変えない

### 事前のスコープ想定と実際の差異

* **P202〜P205(条件付き)が実際に必要になった。** P201 1 回目で A03 が FAIL(ホスト名を解決できないとき python-oracledb が `socket.gaierror` をそのまま送出し、health が 500)、T08 の所見(Oracle に届かない間、プールの close が約 2 分戻らない)を見つけた。どちらも MCP の子プロセスが例外とプロセスの終了を吸収していたために表に出ていなかった退行で、F007・F008 で修正した。着手前には、ドライバがプロセス内に入ることで例外の種類と終了処理の挙動が表に出ることを見込めていなかった。
* **P011・P012(条件付き)も必要になった。** P010 を 3 回実行した(1 回目 4 件、2 回目 1 件の矛盾。主に完了済みスプリントの文書(U001・U006)と T07 の MCP の記述の残り)。
* **P007 の U001・U006 に注記を加えた。** スコープ決定では U002・U003 だけを注記の対象と見込んでいたが、P010 の指摘で U001(パッケージ構成・依存・設定)と U006(イメージの確認コマンド)にも CR-002 の注記が要ると分かった。
* **A04 手順 7 は「削除」ではなく「置き換え」にした。** 着手前は削除を想定していたが、CR-002 の期待する振る舞い「api コンテナで `dbfaq_mcp` の子プロセスが動いていない」を受入テストで確かめるため、子プロセスが無いことの確認に置き換えた。
* **版数を 0.2.0 に上げた(P302)。** API 契約変更の CR のため、SKILL の規則で MINOR を上げた。
* その他のフェーズの対象/対象外は想定どおり(P007 の U004・U005、P008 の T07・T10・T11 は内容を変えず、T07 は語句の修正のみ)。
