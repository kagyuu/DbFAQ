# CR-011 — LLM で作成した Query を保存するとき、要求の先頭 20 文字を名前、要求の全文を説明の既定値にする

## 起票日

2026-10-15

## 起票者

プロジェクトの依頼者(Claude Code セッションでの指示、2026-10-15)。原文: 「LLMで作成したQueryを保存する場合は、ユーザの要望の先頭２０文字を名前のデフォルト値、ユーザの要望の全文を説明のデフォルト値に設定してください。Query保存の(SQLite)の構造に従って、名前の２０文字を縮小しても構いません。また説明をSQLiteのQuery保存テーブルの現在の実装に従って先頭N文字でかっとしてもかまいません。」

## 背景・課題

* LLM で作った SQL を [名前を付けて保存] すると、名前・説明が空(復元中の Query があればその「… のコピー」)で始まり、利用者が毎回名前と説明を考えて書く必要がある。LLM への要求の文がそのまま Query の内容の説明になるのに、使われていない。

## 変更要求の内容

* 入力欄の SQL が LLM で作成したものであるとき、[名前を付けて保存] のダイアログの初期値を次にする(`docs/P002-frontend-spec.md` §2.2.8・§2.2.9)。
  * 名前: その SQL を作ったときの LLM への要求の先頭 20 文字。名前の上限(100 文字。`saved_queries.name`)は 20 文字より大きいため、縮める必要は無い。
  * 説明: その要求の全文。説明の上限(1,000 文字。`saved_queries.description`)を超える場合は先頭 1,000 文字で切る(要求は 2,000 文字まで書けるため)。
* 既定値は初期値にすぎず、利用者はダイアログで書き換えてから保存できる。

## 期待する振る舞い

* LLM で SQL を作成して入力欄に入った後に [名前を付けて保存] を押すと、名前に要求の先頭 20 文字、説明に要求の全文が入った状態でダイアログが開く。
* 要求が 20 文字以下なら、名前は要求の全文になる。
* 要求が 1,000 文字を超えるときは、説明は先頭 1,000 文字になり、そのまま保存できる。
* LLM で作成した SQL を入力欄で編集した後でも、同じ既定値になる。 ★ACCEPTED★(2026-10-16 人間承認)検討: 原文に編集後の扱いの指定が無く、要求との対応が残るとみなして補った/承認理由: 依頼者が実際に動かして「これでよいです」/残存リスク: 大きく書き換えた SQL でも要求から作った名前・説明が入る(保存前に書き換えられる)
* ひな形の作成・保存済み Query の復元・保存で入力欄の SQL が LLM 以外のものに替わった後は、従来どおりの既定値(空、または復元中の Query の「… のコピー」)になる。
* 既定値の名前・説明は書き換えてから保存できる。
