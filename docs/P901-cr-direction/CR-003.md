# CR-003 — 共通部品パッケージ dbfaq_common を dbfaq_api に統合する

## 起票日

2026-09-27

## 起票者

プロジェクトの依頼者(Claude Code セッションでの指示、2026-09-27)。原文: 「dbfaq_common は、config と logging だけになってしまったので。dbfaq_api に統合してください。そのような CR を起こしてください。」

## 背景・課題

* `server/` の uv プロジェクトには `dbfaq_common`(`config.py`・`logging.py`)と `dbfaq_api` の 2 パッケージがある(ADR-007)。`dbfaq_common` は、MCP サーバと backend で共有する部品として作った。
* CR-002 で MCP サーバを廃止したため、`dbfaq_common` を使うのは `dbfaq_api` だけになり、中身も設定の読み込みとログの 2 モジュールだけになった。CR-002 では「分けたままでも困らない」として残した(P003 §1.2 の ★ACCEPTED★)が、依頼者はパッケージを分けておく意味が無いと判断した。

## 変更要求の内容

* `dbfaq_common/config.py`・`dbfaq_common/logging.py` を `dbfaq_api` パッケージに移し、`dbfaq_common` を削除する。uv プロジェクトのパッケージは `dbfaq_api` の 1 つにする。
* 処理の中身(設定ファイルの形式・場所・環境変数での上書き・検証、JSON ログの形式、パスワードのマスク)は変えない。
* 画面・API・データモデル・設定ファイルの形式は変えない。
* 関係する仕様: `docs/P003-backend-spec.md` §1.2・§2.2・§4.5、`docs/ADR.md` ADR-007。

## 期待する振る舞い

* `server/src/dbfaq_common` が無く、`server/pyproject.toml` のパッケージが `src/dbfaq_api` だけである。
* ソースコード・テスト・スクリプトに `dbfaq_common` の import が残っていない。
* 設定ファイル `config.yaml` はこれまでと同じ形式・同じ場所(`DBFAQ_CONFIG`、環境変数での上書きを含む)で読め、不正な設定では起動時にパスワードを含まないエラーになる。
* ログはこれまでと同じ 1 行 1 JSON で標準出力に出て、パスワードを含まない。
* 開発用のスクリプト(`server/scripts/check_oracle.py` など)がこれまでどおり動く。
* 画面・API の振る舞いは変わらず、単体・結合・受け入れ結合のスイートを 2 回続けて実行しても同じ結果になる。

## 影響が想定される範囲

* 画面: 変更なし
* API: 変更なし
* データモデル: 変更なし
* コード: `server/src/`(import の変更)、`server/tests/`、`server/scripts/`、`server/pyproject.toml`
* 関連ADR: ADR-007(1 つの uv プロジェクトに 2 パッケージ)の「2 パッケージ」を 1 パッケージに変える。2026-09-27 に承認された ADR-007 の変更と、P003 §1.2 の ★ACCEPTED★(`dbfaq_common` を残す)を覆す。「1 つの uv プロジェクトにする」という ADR-007 の中心の決定は変わらない。

## 優先度の判断理由

* 低。影響度: 低(利用者から見える振る舞いは変わらない内部構成の整理)。緊急度: 低(現状で困っていることは無い)。ルーブリックで「低」。★ACCEPTED★(2026-09-28 人間承認) 検討: 依頼者から優先度の指定が無く、ルーブリックで仮置きした/承認理由: 依頼者が「低」でよいと確認した/残存リスク: 特になし

## 備考

* 移動先のモジュール名は `dbfaq_api/config.py` と `dbfaq_api/log.py` とする。`logging.py` のままにすると、パッケージ内で標準ライブラリの `logging` と同じ名前になって紛らわしいため。
