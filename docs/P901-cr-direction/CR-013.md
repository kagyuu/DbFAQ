# CR-013 — 保存済み Query の一覧の行をクリックすると [復元] と同じことをする

## 起票日

2026-10-16

## 起票者

プロジェクトの依頼者(Claude Code セッションでの指示、2026-10-16)。原文: 「Queryタブの保存済みQueryサブタブで、保存しているQuery の復元・編集・削除ができます。まず、編集を「名前変更」に変えてください。また、保存しているQueryのある行にマウスがあるときにマウスを右クリックすると「復元」と同じことが起きるようにしてください。」の後半。続く訂正: 「「保存しているQueryのある行にマウスがあるときにマウスを右クリックすると「復元」と同じことが起きるようにしてください。」は「左クリック」の間違えでした。CRを修正してください。」(着手前に訂正を受けて本文を左クリックに直した)

## 背景・課題

* 保存済み Query を入力欄に戻すには、行の右端の小さな [復元] を押す必要がある。行のどこからでも素早く復元したい。

## 変更要求の内容

* SC-02・SC-03 の Query タブ(サブタブ「保存済み Query」)の一覧で、保存済み Query の行の上を(左)クリックすると、その行の [復元] を押したときと同じことをする(`docs/P002-frontend-spec.md` §2.2.8)。
  * 入力欄が編集されていれば、[復元] と同じ確認ダイアログを出す。
  * 行の中のボタン([復元]・[名前変更]・[削除])をクリックしたときは、そのボタンの操作だけを行い、行のクリックとしては扱わない([名前変更]・[削除] で復元が起きない。[復元] で 2 回復元しない) ★ACCEPTED★(2026-10-16 人間承認)検討: 原文は「行にマウスがあるとき」だが、ボタンの操作と重なるとボタンが意図どおり使えなくなるため、ボタンの上は除いた/承認理由: 依頼者「このままでよいです」/残存リスク: 特になし
  * 行の上ではマウスのカーソルを指の形にし、クリックできることを示す ★ACCEPTED★(2026-10-16 人間承認)検討: 原文に指定が無く、クリックできることが分かるよう補った/承認理由: 依頼者「このままでよいです」/残存リスク: 特になし

## 期待する振る舞い

* 保存済み Query の行(名前・説明・更新日時のあたり)をクリックすると、入力欄がその Query の SQL に置き換わり、「復元中: 名前」が表示される([復元] を押したときと同じ)。
* 入力欄を編集してから行をクリックすると、[復元] と同じ確認ダイアログが出て、[キャンセル] なら入力欄は変わらない。
* 行の [名前変更]・[削除] を押したときは、それぞれのダイアログだけが開き、復元は起きない。
* SC-03(PDB)の一覧も同じ。
* [復元] ボタンはこれまでどおり使える。
