# CR-004 — テーブル詳細画面に Query タブを追加し、任意の SELECT 文を作成・実行できるようにする

## 起票日

2026-10-04

## 起票者

プロジェクトの依頼者(Claude Code セッションでの指示、2026-10-04)。原文: 「機能追加をしてください。各テーブルの詳細画面で、スキーマ情報、データのタブがありますが、これに Query タブを追加してください。Query タブでは、任意のSELECT文を作成して実行することができます。SELECT文はスキーマ情報をもとにひな形を作成できるようにしてください。また、FKで連携するテーブルについてはチェックボックスをONにすると、そのテーブルとJOINするSELECT文のひな形を作るようにしてください。作成したSQL文を実行してOracleDBからエラーが返ってきた場合にはそのエラーを表示してください。可能であればSELECT文の何行目の何文字目にエラーがあるのかを表示してください。正常終了した場合には、表形式で表示するようにしてください。」追加の指示(同日): 「画面表示は500行で打ち切りにしてください。それとは別にCSV形式で全てのデータをダウンロードできるようにしてください。」

## 背景・課題

* 第 1 リリースのテーブル詳細画面(SC-02)では、スキーマ情報と、1 テーブルを主キー順に 50 行ずつ見るデータタブしか無い。条件で絞り込んだり、外部キーでつながるテーブルと結合したりしてデータを見るには、SQL*Plus などの別のツールで SQL を書く必要がある。
* DbFAQ の最終目標(保存したクエリを繰り返し実行する)に向けて、まずは画面上で SELECT 文を組み立てて実行できるようにしたい。P001 §10(将来スコープ)の「任意の SELECT の実行」にあたる。

## 変更要求の内容

* SC-02 テーブル詳細に、「スキーマ情報」「データ」に続く 3 つ目のタブ「Query」を追加する(`docs/P001-requirement.md` §4・§6、`docs/P002-frontend-spec.md` §2.2)。
* Query タブには、SELECT 文を書く入力欄と [実行] ボタンを置く。任意の SELECT 文(WITH で始まる問い合わせを含む)を実行できる。
* スキーマ情報(SQLite のスナップショット)をもとに、そのテーブルの全列を並べた SELECT 文のひな形を作れる。
* そのテーブルと外部キーでつながるテーブルを一覧し、チェックボックスを ON にすると、そのテーブルと JOIN する SELECT 文のひな形を作る。
* 実行して Oracle がエラーを返した場合は、ORA エラーコードとメッセージを表示する。Oracle がエラー位置を返す場合は、SELECT 文の何行目の何文字目かを表示する。
* 正常終了した場合は、結果を表形式で表示する。画面に表示するのは先頭 500 行までとし、それより多い場合は打ち切ったことを表示する。
* 画面表示とは別に、同じ SELECT 文の結果の全行を CSV 形式でダウンロードできる。
* backend に、SELECT 文を受け取って実行する API(結果の先頭 500 行を返す API、全行を CSV で返す API)を追加する(`docs/P002-frontend-spec.md` §3、`docs/P003-backend-spec.md` §3・§4)。

## 期待する振る舞い

* SC-02 に「スキーマ情報」「データ」「Query」の 3 つのタブがあり、Query タブを開くと URL が `?tab=query` になり、再読み込みしても Query タブが表示される。
* Query タブを開くと、入力欄にそのテーブルの全列を `column_id` 順に並べた SELECT 文のひな形(主キーがあれば主キーの昇順の ORDER BY 付き)が入っている。
* Query タブに、外部キーでつながるテーブル(このテーブルが参照するテーブルと、このテーブルを参照するテーブル)が外部キー制約ごとにチェックボックスで並び、ON にするとそのテーブルを外部キーの列で JOIN し、その列も SELECT 句に加えたひな形になる。複数を ON にすると、すべてを JOIN したひな形になる。
* HR の EMPLOYEES で DEPARTMENTS への外部キー(EMP_DEPT_FK)を ON にして作ったひな形をそのまま実行すると、エラーにならず結果が表示される。
* SELECT 文を実行して正常終了すると、列名を見出しにした表で結果が表示され、行数と取得時間が表示される。NULL はデータタブと同じく `(null)` と区別して表示される。
* 結果が 500 行を超える場合、画面には先頭 500 行だけが表示され、500 行で打ち切ったことが表示される。
* [CSV ダウンロード] を押すと、同じ SELECT 文の全行(500 行を超えても全行)が、列名の見出し行付きの CSV ファイルとしてダウンロードされる。
* 存在しない列名などで Oracle がエラーを返した場合、`[ORA-00904] ...` のように ORA エラーコードとメッセージが表示され、Oracle がエラー位置を返した場合は「N 行目 M 文字目」が表示される(日本語を含む SQL でも文字単位で正しい位置)。
* SELECT・WITH 以外の文(INSERT・UPDATE・DELETE・DDL・PL/SQL ブロックなど)、複数の文、FOR UPDATE は実行されず、実行できない理由が表示される。Query タブからの操作で Oracle のデータは変わらない。
* 既存のスキーマ情報タブ・データタブ・ER 図の振る舞いは変わらない。

## 影響が想定される範囲

P901時点での見積もりであり、確定した対応範囲ではない(確定は P903 が `docs/P903-cr-records/CR-004.md` に記録する)。

* 画面: SC-02 にタブを追加(Query タブ)。URL の `tab` に `query` を追加
* API: SELECT 文を実行する API を 2 本追加(結果の先頭 500 行の JSON、全行の CSV)。エラー形式にエラー位置を追加。既存 API は変えない
* データモデル: 変更なし(SELECT 文は保存しない。保存は将来の FAQ 機能)
* 関連ADR: **ADR-011 に抵触する。** ADR-011 の決定内容「任意 SQL を受け付ける機能は作らず」と、代替案「任意 SQL の実行: 却下(第 1 リリースの要求に無い。将来 CR)」を覆す。読み取り専用トランザクション(`SET TRANSACTION READ ONLY` と必ず ROLLBACK)は維持する。ADR-005(セル値の文字列化)を Query タブの表示にも適用する。P001 §8.3 の「任意の SQL を受け付ける機能は第1リリースでは作らない」も変わる

## 優先度の判断理由

* 中。影響度: 高(主要画面 SC-02 に新しい機能を加え、DB に任意の SELECT を発行する入口ができる)。緊急度: 低(SQL*Plus など別ツールで代替できる)。ルーブリックで「中」。★ACCEPTED★(2026-10-09 人間承認)検討: 依頼者から優先度の指定が無く、ルーブリックで仮置きした/承認理由: 依頼者が受け入れた/残存リスク: 特になし
