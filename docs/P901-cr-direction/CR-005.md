# CR-005 — Query の保存・復元(テーブルごと)と、PDB 画面(ドラム缶アイコン)・PDB の Query・運用 Query のひな型

## 起票日

2026-10-07

## 起票者

プロジェクトの依頼者(Claude Code セッションでの指示、2026-10-07)。原文: 「今夜は、各テーブルのQuery作成画面で作ったSQLを名前と説明付きで保存できるようにしてください。また、保存したSQLをQuery作成画面に復元できるようにしてください。Queryの保存はテーブルごとにするようにしてください。データベースのスキーマが変更され、テーブルが亡くなった場合でもQueryは残したままにしておいてください。将来同名のテーブルが復活した場合はそのQueryが再び使えるようにしてください。また、テーブルとは関係のないデータベース（PDB)の情報を得るQueryも取り扱えるようにしてください。メイン画面にテーブルの他に、ドラム缶（記憶装置）のアイコンを表示して、そのアイコンをクリックすると、PDBの情報の表示とテーブル同様のQuery実行ができるようにしてください。PDBのQueryには、次のひな型を用意しておいてください。１. USER表領域の大きさ、2. テーブル.カラムごとのLOB領域の大きさと実データの合計容量、そのほかにも PDB を運用するうえで頻出の Query があれば登録してください。」

## 背景・課題

* CR-004 で SC-02 に Query タブを作ったが、SQL は保存されず、画面を離れると消える。運用で繰り返し使う SQL を毎回書き直す必要がある。DbFAQ の最終目標(FAQ = 保存したクエリを繰り返し実行する)の中心の機能が無い(P001 §10 の将来スコープ)。
* 表領域の使用量や LOB の容量のように、特定のテーブルに属さない PDB 全体の情報を見る手段が無い。SQL*Plus で辞書ビューを問い合わせる必要がある。

## 変更要求の内容

* SC-02 の Query タブで、入力欄の SQL を**名前と説明を付けて保存**できる。保存先は**そのテーブル(スキーマ名 + テーブル名)ごと**とする(`docs/P001-requirement.md` §6 SC-02 Query タブ、`docs/P002-frontend-spec.md` §2.2.6)。
* 保存した SQL の一覧を Query タブに表示し、選んだ SQL を**入力欄に復元**できる。保存済みの SQL の上書き保存・名前と説明の変更・削除もできる。
* 保存した SQL は SQLite に置く(`docs/P002-frontend-spec.md` §4)。スキーマの再読み込みでテーブルが無くなっても**保存した SQL は消さない**。後で**同じ名前のテーブル**(同じスキーマ名・テーブル名)がスナップショットに戻れば、そのテーブルの Query タブで再び一覧に出て使える。
* 特定のテーブルに属さない **PDB の Query** も保存・復元・実行できる。
* SC-01(メイン画面。ER 図)に、テーブルとは別に**ドラム缶(記憶装置)のアイコン**を表示する。クリックすると新しい画面(PDB 画面)へ移り、**PDB の情報**の表示と、テーブルと同様の **Query の作成・実行・保存・復元**ができる。
* PDB の Query には、**ひな型**を最初から登録しておく: (1) USER 表領域(USERS)の大きさ、(2) テーブル.カラムごとの LOB 領域の大きさと実データの合計容量、(3) その他、PDB の運用で頻出の Query。
* backend に、保存した SQL の一覧・登録・更新・削除の API と、PDB の情報を返す API を追加する(`docs/P002-frontend-spec.md` §3、`docs/P003-backend-spec.md` §3・§4・§5)。

## 期待する振る舞い

* SC-02 の Query タブで、SQL を名前(必須)と説明(任意)を付けて保存すると、そのテーブルの保存済み Query の一覧に出る。
* 保存済み Query の一覧から 1 件を選んで復元すると、入力欄がその SQL に置き換わり、そのまま実行できる。
* 保存済み Query は、保存したテーブルの Query タブにだけ出て、別のテーブルの Query タブには出ない。
* 保存済み Query の SQL の上書き、名前・説明の変更、削除ができる。同じテーブル内で同じ名前の Query は登録できず、理由が表示される。
* 保存した Query は、backend の再起動・コンテナの再作成の後も残っている。
* スキーマの再読み込みで、保存済み Query のあるテーブルがスナップショットから無くなっても、保存済み Query は SQLite から消えない。
* その後、同じスキーマ名・テーブル名のテーブルがスナップショットに戻ると、そのテーブルの Query タブに保存済み Query が再び出て、復元・実行できる。
* SC-01 に、テーブルのノードとは別にドラム缶のアイコンが表示され、クリックすると PDB 画面に移る。
* PDB 画面で、PDB の情報(コンテナ名、DB のバージョン、文字セット、接続ユーザーと既定の表領域、表領域の割り当て、セグメントの使用量など)が表示される。接続ユーザーの権限で読めない情報は、その項目だけ読めないことが表示され、他の項目は表示される。
* PDB 画面で、Query タブと同様に SELECT 文を実行でき(先頭 500 行、CSV、エラー位置)、名前と説明を付けて保存・復元できる。
* PDB の Query の一覧には、最初から「USERS 表領域の大きさ」と「テーブル.カラムごとの LOB 領域の大きさと実データの合計容量」のひな型と、その他の運用 Query のひな型がある。
* ひな型の「テーブル.カラムごとの LOB 領域の大きさと実データの合計容量」を開発用 Oracle の HR で実行すると、EMPLOYEE_FIGURE.FIGURE の LOB セグメントの大きさと実データの合計が表示される。
* 既存の ER 図・スキーマ情報タブ・データタブ・Query タブ(ひな形・実行・CSV・エラー位置)の振る舞いは変わらない。

## 影響が想定される範囲

P901時点での見積もりであり、確定した対応範囲ではない(確定は P903 が `docs/P903-cr-records/CR-005.md` に記録する)。

* 画面: SC-01 にドラム缶のアイコン。SC-02 の Query タブに保存済み Query の一覧と保存の操作。PDB 画面(SC-03)を新設
* API: 保存済み Query の CRUD(4 本)、PDB の情報(1 本)を追加。既存 API は変えない
* データモデル: SQLite に保存済み Query のテーブルを追加(マイグレーション 0002)。スナップショットのテーブルとは外部キーで結ばない(テーブルが消えても残すため)
* 関連ADR: ADR-002(マイグレーション)・ADR-003(スナップショットの置き換え)・ADR-008(SQLAlchemy Core)・ADR-011/015(利用者の SQL の検査と読み取り専用トランザクション)の範囲内。**P001 §6 の Query タブの「SQL も結果も保存しない」と、P002 §4 の「スナップショットだけを保存する」の記述を変える**

## 優先度の判断理由

* 中。影響度: 高(DbFAQ の最終目標である FAQ の保存・再実行の中心機能で、主要画面に関わる)。緊急度: 低(SQL を手元に保存して貼り付けることで代替できる)。ルーブリックで「中」。★ACCEPTED★(2026-10-09 人間承認)検討: 依頼者から優先度の指定が無く、ルーブリックで仮置きした/承認理由: 依頼者が受け入れた/残存リスク: 特になし

## 備考

* 依頼の原文は「テーブルごとの Query の保存・復元」と「PDB 画面と PDB の Query・ひな型」の 2 つの要望を含むが、**1 つの CR にまとめた**。理由: PDB の Query は「テーブルと同様の Query 実行」「Query を取り扱えるように」とあり、保存・復元の仕組み(データモデル・API・画面部品)をテーブルの Query と共有する。分けると CR-006 が CR-005 の完成に全面的に依存し、設計・テストを 2 回に分けて同じ箇所を直すことになるため。
* 依頼者の過去の方針(既定値で進め、想定は ★FIXME★ で残す)に従い、確認の質問はせず、Agent の想定は P002・P003 に ★FIXME★ を付けて記録する。
* 開発用 Oracle の接続ユーザー `hr` は DBA_* ・V$ の多く(DBA_DATA_FILES、DBA_LOBS、V$SESSION など)を読めない(2026-10-07 確認。ORA-00942)。権限の要るひな型は、そのことを説明に書いたうえで登録する。
* 対象外: FAQ のバインド変数・カテゴリ・タグ・検索、実行履歴、テーブルが無くなった保存済み Query の一覧画面(P001 §10 の将来スコープのまま)。
