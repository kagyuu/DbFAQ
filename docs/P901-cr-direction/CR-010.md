# CR-010 — Query タブにサブタブ(JOIN・保存済み Query・自然言語で SQL を作成)を設け、SQL の入力欄・実行・CSV・結果は共通領域として常に表示する

## 起票日

2026-10-15

## 起票者

プロジェクトの依頼者(Claude Code セッションでの指示、2026-10-15)。原文: 「Query タブが複雑になってしまっています。情報を整理するために Query タブの下にさらにサブタブを作って、JOIN、保存済みQuery、自然言語で SQL を作成 に分けてください。実装上は、もとのまま一つのページで、どれかのサブタブをクリックすると、そのほかの二つが非表示になるようにするので構いません。Query入力のtextarea および実行、CSVダウンロード、データ表示は共通領域として常に表示しておいてください。」

## 背景・課題

* CR-004・CR-005・CR-007・CR-008 で Query タブに JOIN の選択・保存済み Query の一覧・LLM で SQL を作成の部品を順に足してきた結果、1 画面に縦に並ぶ部品が多く、SQL の入力欄と結果が画面の下に押し出されて見づらい。

## 変更要求の内容

* Query タブ(SC-02・SC-03)の上部に**サブタブ**を設け、「JOIN」「保存済み Query」「自然言語で SQL を作成」を切り替える(`docs/P002-frontend-spec.md` §2.2.6・§2.2.8・§2.2.9・§2.3.3)。
* どれかのサブタブを選ぶと、そのほかのサブタブの部品は非表示になる。実装は 1 つのページのまま、表示・非表示を切り替えるだけでよい(人間の指示)。
* SQL の入力欄(textarea)、[実行]・[CSV ダウンロード]、結果(行数・取得時間・表・エラー)は、サブタブの外の**共通領域**として常に表示する。

## 期待する振る舞い

* SC-02 の Query タブの上部に「JOIN」「保存済み Query」「自然言語で SQL を作成」のサブタブがあり、1 つを選ぶとその部品だけが表示され、ほかの 2 つの部品は表示されない。
* どのサブタブを選んでいても、SQL の入力欄・[実行]・[CSV ダウンロード]・結果(行数・表・エラー)が表示され、使える。
* サブタブを切り替えても、入力欄の SQL・JOIN の選択・LLM への要求・作成の結果・結果の表は失われない。
* SC-03(PDB)の Query タブにも同じサブタブがある(JOIN は無いので「保存済み Query」「自然言語で SQL を作成」の 2 つ)。 ★ACCEPTED★(2026-10-16 人間承認)検討: 原文は SC-03 に触れていない。SC-02 と同じ部品のため同じ構成にした/承認理由: 依頼者が実際に動かして「これでよいです」/残存リスク: 特になし
* 既存の JOIN・ひな形・保存・復元・LLM の作成・実行・CSV の振る舞いは変わらない。
