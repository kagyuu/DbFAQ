### T08 の所要時間(問題あり)

- `--durations` で T08 だけが 131.97 s かかっていた(他は最大 2.1 s)。
- 最小再現(`OracleClient` を port 1 の設定で作り、snapshot・ping・close を順に計測)で切り分けた: snapshot・ping はそれぞれ 3.0 s で `DPY-4005`(期待どおり)。**`close()` が 123.87 s かかった。**
- さらに python-oracledb だけの最小再現(`oracledb.create_pool_async(dsn="localhost:1/FREEPDB1", min=1 または 0, getmode=TIMEDWAIT, wait_timeout=3000, tcp_connect_timeout=3)` を作り、acquire の有無・待ち時間を変えて `pool.close(force=True)` を `asyncio.wait_for(..., 40)` で計測)で、4 条件すべてで close が 40 s 以内に終わらなかった。Oracle に届くときの close は一瞬(dev の uvicorn の停止は 0.21 s)。
- 判断: **python-oracledb 26.0.0 の非同期プールの close が、リスナーに届かない間は長く待つ**という実行環境(ドライバ)側の挙動。アプリの誤りではないが、CR-002 で backend がプールを持つようになったため、Oracle に届かないときの **api の停止・再起動(lifespan の終了)が最大 2 分止まる**。MCP の時代は子プロセスごと終了していたので表に出なかった。
- 次工程への申し送り: P103 では修正しない(規定どおり)。P201 で修正の要否を判断し、P202 へ引き渡す。ドライバの挙動は `docs/ArchitectureHandbook.md` §9 に記録する。
